# PackHub 全系统细化审计

> 日期：2026-11-05 ／ 口径：34 个 CLI 子命令、全部 `<cmd> --help`、源码入口、219 项测试、示例包与 registry 实测。
> 目的：找出“像创作台只有草稿却标完成”这类**功能面存在但端到端没走通**的漏项，而不是复述 README。

## 结论

- 功能清单里已没有 `[todo]` / `[part]`，但**清单本身仍然按“有这条命令/有这张表”验收**，不保证端到端。
- 本次审计实际找到 **30 个漏项/不一致**；后续已全部修复，并补了对应测试或实测。
- 最严重的三类：**CLI 参数被静默忽略**、**发布/初始化组合起来必然失败**、**状态/配置损坏时直接抛堆栈**。

## 审计方法（可复现）

```bash
pnpm check
pnpm ui:audit
for c in $(packhub --help | ...); do packhub $c --help; done
pnpm packhub plan examples/code-review
pnpm registry:verify-all
# 手工：init → lock → run → publish；损坏 state.json 后 uninstall；未知 --flag；plan --index
```

## 修复结果

AUD-01..30 全部修复。关键落点：

- CLI：未知参数退出 2、`--json` 全覆盖、`plan --index`、帮助文案、completion 参数、publish 失败回滚。
- 清单/图：`optional` 级联跳过、`requires.agent` 校验与展示、metadata 进索引与包页。
- 签名：`sign` / `verify-sig` 按扁平化计划签验，flatten 保留有效签名。
- 状态：doctor 比对 `active.json`、state 补写 version、activate 自动复核、versions 显示动作/文件状态。
- 服务端：本地与 Hub 请求体上限、ETag / Cache-Control、market staging 清理。
- 市场：admin token 落盘 sha256 + 轮换接口 + 审计日志。
- 运维：`registry:verify-all:offline`、`verify:examples` 矩阵、CI 增加示例矩阵。

验证入口：

```bash
pnpm check
pnpm verify:examples:offline
pnpm registry:verify-all:offline
pnpm web:build && pnpm ui:audit
```

## 2026-11-05 追加

第二轮按「下一步」清单补了四块，并修掉一个被视觉基线抓到的真实缺陷：

- `state` 块：持久状态目录、`state.dir` 动作、默认保留 / `retain: remove`。
- 多 target 锁：`lock.plans` 为每个声明 target 存快照；`add` / `diff` / `update` / 索引门禁按 target 核对。
- 版本镜像硬链接：安装写入改原子替换，避免写穿旧镜像。
- Claude Code 全局 MCP adapter：宿主 CLI user scope，`hostMcp` 记名，doctor/remove 接上。
- 视觉回归：截图基线 + `ui:audit` 捕获未处理异常与空页面；因此发现 `/packs` 对旧索引缺字段时白屏，已修并重生成索引。
- 市场：SQLite（WAL）+ 旧 JSON 自动迁移 + `/admin` 审核/统计页。

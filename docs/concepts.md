# PackHub 概念

## 一句话

Pack 是配方，Instance 是装好的环境，Harness 是跑 Agent 的宿主，Adapter 负责把配方译成宿主认得的形态，Verification 回答“装完能不能用”。

## 名词

### Pack（整合包）

一份可复用的 Agent 环境配方：装哪些资源、资源之间怎么接、对目标宿主有哪些约束、装完怎么验。

Pack 不是资源的压缩包。没有接线与验收条件的资源集合只是清单，不是 Pack。

Pack 是作者侧产物：可版本化、可分发、可被解析。

### Resource（资源）

Pack 里的一条能力声明：类型（技能、工具连接、指令、知识、配置、可执行件）、来源、指向的内容。

资源不是独立分发单元；同一个资源可以出现在多个 Pack 里。

### Source（来源）

资源从哪来：本地文件、包仓库、代码托管、包管理器、URL。

来源决定获取方式，也决定完整性可以校验到哪一层。

### Composition（接线）

资源之间的关系：谁提供什么能力、谁需要什么能力、谁占用哪个可替换位、谁依赖谁。

接线描述约束，不描述执行顺序。它让 Pack 从“资源合集”变成“能一起工作的组合”。

### Manifest（清单）

Pack 的声明：资源、接线、目标、约束、验收条件。

清单只写作者希望它成为什么，不写装完之后实际是什么。

### Lock（锁）

对清单的一次解析结果：每个资源固定到具体版本或提交，附上完整性信息，使同一份清单在不同时间、不同机器上解析到同一批东西。

锁不是安装记录。它描述“应该装成什么样”。

### Plan（计划）

针对一个具体目标与安装根，把清单与锁展开成的一组动作，是纯数据。

计划可以比较、可以预演；它不执行，也不记事实。

### Install（安装）

按计划把文件写进目标、把配置合并进去、把能力登记给宿主的过程。

安装有事务性：要么整体成立，要么回到开始前的状态。

### State（状态）

安装留下的事实：写过哪些文件、装的是哪个版本、计划哈希是多少。

状态是安装的账；它不替代清单，也不替代锁。

### Verification（验证）

装完之后判断“能不能用”，而不是“文件在不在”：宿主有没有读到指令、资源是不是可见、命令能不能跑、语义有没有保持。

验证产出报告。报告有等级，区分可安装、可启动、资源可用、语义保持、行为通过。

### Baseline（基线）

一个实例与它来源 Pack 的关系记录：来自哪个 Pack、哪个版本、按哪份计划装的，以及装进去的托管文件。

基线让“上游更新”和“本地修改”可以对照。基线不是快照；快照是某个时刻的副本，基线是持续的来源关系。

### Harness（宿主）

真正运行 Agent 的东西：模型循环、工具执行、上下文管理、交互界面。

Harness 不归 PackHub 实现。PackHub 只识别它能吃什么、该接到什么位置。

### Adapter（适配）

把 Pack 的通用声明翻译成某个 Harness 认得的形态：能力清单、落点、格式、降级方式。

适配器回答“这个 Pack 在它上面能装成什么样”，不决定装不装，也不执行安装。

### Instance（实例）

一个独立的 Agent 环境：配置、数据、密钥、缓存、端口、进程、会话各归各，互不影响。

实例是“装好的环境”，Pack 是“配方”。一个 Pack 可以生出多个实例；一个实例只来自一个 Pack 版本。

实例不是目录别名：目录是载体，身份是记录。

### Launcher（启动器）

围绕实例的运维层：发现宿主、准备环境、启动进程、管端口、收日志、诊断崩溃、把界面交出去。

启动器不重新实现 Harness，也不重新计算安装计划。

### Registry（仓库）

Pack 的索引与分发面：版本目录、不可变、可按名取用。

仓库只读，写入不发生在这一层。

### Market（市场）

Pack 的上传、审核、统计与下架。

市场是仓库的写端；它不执行 Pack。

### Hub

面向人的只读站点：包页、资源页、计划预览。

Hub 是仓库的展示面。

## 关系

```text
作者 ──写──> Pack ──解析──> Lock ──展开──> Plan ──执行──> State
                │                              │
                │                              └──> Instance
                │
                ├──Adapter──> Harness 的落点与能力
                └──Registry──> 分发

Instance ──Launcher──> Harness（进程、端口、日志、界面）
Instance ──Baseline──> Pack@version
Verification ──> Report
```

## 边界

- **声明、解析、执行、事实。** 清单是作者声明，锁是一次解析，计划是要做的动作，状态做完之后的记录。四者不能互相替代。
- **Pack 与实例。** Pack 不变，实例可变；Pack 一对多实例，实例只认一个 Pack 版本。
- **计划与报告。** 计划说“要做什么”，报告说“成了没有”。
- **基线与快照。** 基线是来源关系，用来做三方对照；快照是某一刻的副本，用来回退。
- **适配与执行。** 适配器只给落点与能力，执行层只按计划写；执行层不重新判定该不该装，适配器不写盘。
- **安装与启动。** 安装管文件与配置，启动管进程与环境；两者不互相调用对方的判断。
- **PackHub 与 Agent 内部。** Agent 循环、上下文、工具执行、会话内容归 Harness；PackHub 只管理环境，不实现运行时。

## 判据

- 一条能力，如果去掉 Pack、实例、Harness 适配任一个词仍然成立，它大概率属于 Harness，不属于 PackHub。
- 一份数据，如果删掉之后能从别处重算出来，它是派生；重算不出来，它就得按事实管理。
- 一个对象，如果只有路径没有独立身份，它是目录；有了与名字无关的标识，才是实例。

# PackHub 概念

### Pack（整合包）

一份可复用的 Agent 能力整合：不意味着把 Agent 需要的功能放在一起就够；它强调的是这些功能能作为一个有机的整体给出。

Pack 不是资源的压缩包，哪怕拥有依赖关系也不能自动成为有机整体，作为Pack，需要创作者为它调整整个Pack中所有资源的关系，并以特定的体验给出。

### Resource（资源）

Pack 里的一条能力声明，它相对于Agent而言，而非整个harness，因此它可以是SKILL、工具、脚本、普通提示词...只要它能够使Agent稳定的表现出某种能力。但不会是ui优化等内容。

### Source（来源）

来源是资源对内容的引用：它指向内容所在的位置，并通过它能够获取被引用的资源。

引用可以指向包内文件、另一份包、代码仓库、包管理器或一个 URL——形式不限，只要能定位到内容并取回来。

### Composition（接线）

接线是资源之间的一组声明关系：谁提供什么能力、谁需要什么能力、谁占用哪个可替换位、谁依赖谁。

它描述约束，不规定先后。

### Manifest（清单）

清单是 Pack 的书面声明：有哪些资源、彼此怎么接、装到哪些目标、有哪些约束。

它是 Pack 打包的重要依据。

### Lock（锁）

锁是清单的一次解析结果，它确保打包时候的资源一致性，避免资源的变动导致包功能产生问题，同时也确保版本一致性。

### Packaging（打包）

打包是把 Pack 收成一个可交付文件的过程：让包离开作者的工作目录之后仍然完整，使Pack能够安装到其他不同环境的harness中。

清单、锁，和要随包带走的内容，一起进同一个归档。

### Plan（计划）

计划是一次安装的动作安排：把 Pack 展开到某个目标上，列出要做哪些事、按什么顺序做。

### Install（安装）

安装要求把 Pack 落进一个实例的过程，它使宿主在实例里能用上能够开箱即用的装配Pack所提供的能力和体验。

安装具有事务性，要么所有资源整合安装成功，要么全部不安装。

安装一个Pack意味着在宿主中创建了一个Harness的实例配置[具体见下]

### State（状态）

状态记录了安装时装的内容、写过哪些东西，它记的在机器上已经发生记录，回滚、卸载、漂移检查都读它

### Harness（宿主）

宿主是支持 Agent运行的那一层，是整合包能够运行的底层，如果要比喻的话，就像是MC中的原版，不同的harness就是不同实现或版本的MC。

模型循环、工具执行、上下文、界面都在它那里。

### Adapter（适配）

适配是 Pack 与某个宿主之间的翻译：把通用声明换成那个宿主认得的说法。

它只回答这个 Pack 在它上面能落成什么样。

### Instance Profile（实例配置）

实例配置是安装落在宿主上的一份可启动环境：配置、数据、密钥、缓存、会话[会话可以理解为mc的一个存档]各有自己的位置。

它有独立身份，不是一条路径；一个 Pack 可以生出多份实例配置。启动器读它、起进程，把它跑成实例；它本身不随启动改变。

### Instance（实例）

实例是宿主跑起来之后的那份运行体：进程，以及它占用的端口。

它可以从一份实例配置启动，也可以直接启动。

### Launcher（启动器）

启动器是实例配置的管理者，也是实例的启动者。

它列出、创建、复制、切换、删除实例配置；安装、更新、卸载从它发起，写盘与登记仍在安装那一步。启动之后，实例的起停与异常归它照看。

### Registry（仓库）

可以专门创建一个仓库，用于存储 Pack 与维护不同版本的Pack。

仓库以Pack为最基础的操作单元，并提供相关的增删改查能力。

### Market（市场）

市场在仓库的基础上提供 上传、审核、统计、下架等功能;

甚至可以提供权限鉴定等能力。

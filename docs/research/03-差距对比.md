## 四、研究之外，代码里对得上的几处

- **`server` 已不是 target。** 它曾经与 `dir` 是同一张表（逐项相同），后来确认没有差异，已从 `TargetId` 与 schema 删除。
- **`pack` 默认不带本地资源。** 不带 `--vendored` 只打清单、锁、签名；含 `./` 来源的包现在会直接拒绝（`pack.ts` 守卫），不再产出装不上的归档。
- **两处接线断了。** 详情页读 `readme`/`changelog`，`server.ts` 不返回（UI-02）；站点发布只拷 `index.json` 与 `.phub`，不带 `web/dist`（REG-03）。
- **`paths` 与 `composition.needs` 已从 schema/types 删除**（分别与 `vars`、资源级 `provides/needs` 重叠）；02 仍按两条功能记，属过时。

## 五、差距逼出来的几个决定

1. **实例边界。** 02 的实例根含数据、配置、缓存、日志、状态；现在的 install 直接写当前目录或 harness home。先定「实例 = 一份 harness home 还是一个项目目录」，IST 的其余条目才有落点。
2. **target 是枚举还是注册表。** 现在 schema、types、CLI 三处写死四个值；ADP-05.4 要求第三方注册新 harness。
3. **验证等级要不要落字段。** L0–L4 目前只有文字，VAL-04 是空的。
4. **共享资源的归属。** 全局 skills 与项目 skills 各有一份 state，没有引用计数，IST-06 与 REL 都压在这上面。

## 六、附：MC playbook 里可借鉴的做法（建议，不是需求）

- **实例 = 独立目录。** MC 的 `mods/`、`config/`、`saves/` 各归各；对应 skills、配置、会话与状态。
- **先写这个包解决什么问题。** playbook 的 A1；现在只有 `metadata.description` 一个位置，PACK.md 要不要立规矩是写作约定。
- **加载器 ≈ harness。** PackHub 的对应物是 target 加 harness 版本范围（PACK-01.2 的版本范围仍缺）。
- **冒烟脚本当验收。** 启动到主菜单、走一圈、`/reload`、看日志尾部；对应 VAL-07 的场景库。
- **冲突预判表。** 功能重复、Mixin、配方、标签、能量单位、世界生成、客户端/服务端；对应 PACK-04.4，也是「为什么允许用户改」的理由。
- **记选型与配置改动。** `notes/mods.md`、`notes/config.md`；对应 PACK-04.5。
- **配置锁定。** MC 用 `serverconfig` 压制客户端改动；对应 REL-03。
- **数据包/资源包的覆盖规则。** 同路径覆盖、后加载覆盖先加载、`pack_format` 不匹配静默忽略；对应 overlays 与版本不匹配的显式提示。
- **全局数据包「装完就带」。** OpenLoader/Paxi；PackHub 的安装即生效是同一件事。
- **`options.txt` 只在首次生效。** 对应实例初始化默认值。
- **安装后引导。** 装完让 agent 发一条引导消息，而不是只说「你好」。
- **打包 ≠ 发布。** `dist/` 每次重建；PackHub 的 `pack` / `publish` 已经分开。
- **导出后自检。** 干净目录、断网、zip 根结构、大小对账、服务端包单独装；对应 runner 与 PACK-05.3。
- **CI 校验清单与实际文件一致。** packwiz 的 `refresh`；对应 `registry:check`。
- **分发形态不止一种。** zip / manifest / mrpack / packwiz；PackHub 没有「清单 + 外部下载」这种形态。
- **发布检查表。** 图标、截图、CHANGELOG、许可、备用下载；对应 publish 门禁的扩展项。

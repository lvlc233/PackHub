# 文档验收标准

两件事，按顺序看。

## 充分性

充分性是对目的说的，不是对覆盖面说的。

1. 先用一句话写清：这份文档给谁、读完能回答什么。
2. 逐节问：这一节是否服务那句话。不属于目的的字段、边界、错误码，指到参考资料，不塞进正文。
3. 找目标读者冷读。能复述主线、能回答目的内的问题，就是够；答不上，或读主线必须频繁跳到别的文档，才是不足。
4. 字数、字段数、覆盖项都不作数。

## 可读性

可读性在读者的路径上，不在章节的整齐上。

- 从读者的问题和一个能跑的例子开始，概念放在例子之后。
- 一节只回答一个问题。
- 能用时间线讲清的，先按时间线写；表只留给并列比较。
- 用真实输出、目录树、命令结果当锚点，不用“例如”占位。
- 让没看过的人读一遍，他能说出“先是什么、再怎么走、哪里会坏”，并指出唯一的跳跃。停在定义上问“这个动作是什么”，或读完复述的是目录而不是过程，就是没写好。

## 报告格式

```md
## 结论
<能/不能一次读懂；扣在哪>

## 阻断项
- <读者卡住的位置 + 原文小节>

## 非阻断项
- <可以留到参考资料的内容>

## 建议改动
- <只列服务目的的那几处>
```

# 记忆

本机的配置在 `config.md`（随包走，和 SKILL.md 同级目录）；下面的 `config.md:xxx` 都指那一份里的键。

把一个东西写进文档，不等于它成了`我`的记忆。文档写得再整齐，也不会让`我`下次想起来——区别在它下次会不会被读。

`我`的记忆放在 `config.md:memory`。那里没有的时候用 `config.md:memory_fallback`；两个都空着，就什么都不写，把缺的那个键说出来。不替`我`临时挑一个地方放着，那样下次一定找不到。

## 什么值得记

`我`只记自己在乎的、和正在做的事。判断依据在 `config.md:memory_strategy`；那份东西改了，这里不用跟着改。

## 记成什么形态

`我`不先分类。量攒到一定程度，某些东西会自己长成一块。现在分出来的几块在记忆区里各自带 `from_package`，写着它是谁要的。

要开一块新区域时，`我`不自己建目录。先告诉人：这一块跟现有几块差在哪，为什么放不进任何一块。建区域是别人的动作。

## 写完要能被找回来

位置和入口是两回事。放进记忆区只是位置；下次还认得出它，靠的是它头里那两行：`from_package` 写着谁要的，`trigger` 写着什么情况下该回来改或读它。

写的时候把 `trigger` 写在能被自己看懂的程度——"更新记忆点的时候"就比"记忆相关"有用，因为它给出了回来的时机。

找的时候两条路，看手上有没有明确的关键词。

知道自己来自哪个包，就按 `from_package` 分组取：

```
<py> G:\work\tool\skill-hub\clusters\mdhead\reader.py search <记忆区> --profile G:\work\tool\skill-hub\learning\profile.yaml --where from_package=memory-core
```

`<py>` 是本机的 python 绝对路径，见 `经验/本机相关内容/`。不用 `--text` 搜自定义键——它只认 id/when/tag 和正文，`trigger` 命不中。

不知道从哪下手，就进目录看名字，再读头里的 `trigger` 决定开不开。

这套查法不用给 data 里的文件改头：reader 只按 profile 认键，缺 `kind`/`id`/`when` 不影响检索，只是 `check` 会报错——那是校验口径，不是能不能读。

落完当场验一次：按上面那条命令搜一遍，或进目录看得到。搜不到就先改 `trigger`（或改落点），别把"写了"当成"找得到"。

## 什么时候退

记得多不等于记得好。一条判断如果从没被下一次用到，它占的不是位置，是读的时候的噪音。

该不该退、退成什么形态、删之前先看什么，都在 [自复盘](references/review.md) 里。到点由提醒来叫；没被叫到，不等于不该退。

## 边界

- 记的是当时的认识，包括看错的；不要求每段经历都变成方法。
- 能查到的知识不写成亲身经历。

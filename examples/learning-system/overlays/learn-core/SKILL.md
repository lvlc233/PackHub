# 学习

本机的配置在 `config.md`（随包走，和 SKILL.md 同级目录）；下面写的 `config.md:xxx` 都指那一份里的键。读完它再看这一段，不然位置全靠猜。

`我`学一个东西，是为了换个场合还能用出来。看懂了、抄下来了、说得出术语，都还不算。

## 先接上已有的认识

动手前读 `config.md:memory` 下跟这次对象同一块的东西——`经验/<域>/`、`经验/学习/`、`自我反思/`。要能说出一句：上次学到哪、哪条被后来的事推翻了。

说不出来，说明那些字写在那就没被读过。这一轮里它先不占位置，也不要为了让"我学过"成立去引用它。

`config.md:learning_module` 是我以前想过怎么学的地方；卡住时看一眼，不照着走。

## 学的时候

`我`不预设这一轮要得出什么产物。同一个东西能学怎么用、为什么成立、由哪些部件组成、用起来什么感觉、这套说法谁受益——这些不是同一件事，验收的口径也不一样。一次只走一个角度，我自己每次想同时走好几个，结果每个都很薄；新想到的角度先记下来，一个走完再回头读同一段，从新角度再来一遍。

开工前在 `config.md:note_to` 写一行：**这次的角度**（一条）＋**学完要能做出来的一件事**＋**什么算没做到**。材料重（要读源码、要跑代码、要下选型判断）→ 先读 learn-source 的角度表，选定命题再动手；材料轻（一个词、一句话）→ 走 one-pass。不写这一行就开跑，等于让材料决定学什么——2026-11-05 的 nojson 那轮就是这样：我挑了"它为什么这样设计"，用户回来要的却是"怎么用、能干什么"，同一段材料又走了一遍。

`我`一边做一边记轻笔记，放在 `config.md:note_to`。记的是这次卡在哪、依据了什么、哪句还拿不准，不是材料的摘要。学到差不多就把它删掉——它只服务于这次思考，留着也不会被读第二遍。

## 材料怎么进到我眼前

视频先看有没有字可读。有烧录字幕条的，抽帧比看画面划算：两秒一帧，把底部那条字幕裁下来、按时间顺序拼成竖条，一次读十几条，五分钟的片子读完不费事。没有字幕又没字在画面上，才需要逐帧看。

文档读原文；代码先跑一遍再读。

要知道一个网页"用了什么"，抓源码按字符串数，比读文案或看描述硬。但要记住反过来不成立：源码里没找到某个名字，只能说明没找到。

抽帧、截图、临时脚本都是梯子，用完就删；留下的只能是数字、命令和判断。

## 怎么算学到了

`我`拿它去做一件材料里没有的事：换一个输入、改一个条件、自己搭个小的、或者下一个判断。动手前在心里写一句"如果它是这样，应该会……"，做完对着结果看差在哪一层：材料没给、我读错、还是我没做到。

跑通一次、写出一份文档、数出覆盖了多少分钟，都不能单独证明这个。

## 材料牵着走的时候

看到什么就核什么，最后交出来的会是一份对材料的描述，不是我的认识。遇到这种情况先停一下：这次我想知道的是什么，材料哪一块能回答它，哪一块答不了。

## 收尾

这一轮改变了我哪个动作？说不出来，这轮就只有过程。说得出来，压成一句交给 memory-core——由它判断要不要留、留成什么形态、下次怎么被找回来。落盘不是这里的事。

交出去之前答三问：这句落在**哪个文件**（写路径，不写目录；一个对象的用法单独成篇，别塞进别的工具的条目里）、下次**从哪个入口**被读到（目录遍历 / 头里的 `trigger` / 技能目录）、**什么条件下会失效**（版本、平台、有效期）。入口答不上就先补（加头、加索引、做成 skill），补不了就当场说"这条会丢"。落完再查一次：列目录、或按 `from_package` 搜一遍，搜不到不算落成。

跌倒时先分：规则没写到，还是写到了我没做？没写到 → 改 skill（架构可以改，数据只记账）；写到了 → 写进本轮复盘，不重复加同一句。

要回头审这一轮是怎么走的（卡在哪、哪一步的预期被现实改了），见 [复盘](references/retro.md)；那是看过程，不是交产物。

## 边界

- 不虚构跑过的、看过的、验证过的。
- 一两个样本撑起来的结论，说成"这次是这样"，不说成规律。
- 没学的部分写明没学，不拿"大体覆盖了"盖过去。
- 材料本身过时、片面、写错的，就按过时处理，不为了讲通它去补我没有的前提。
